### After the R0 capture (rev 5 in progress)
- **The captured body contradicted the spec.** There is no TER-branded leg in the real answer: the regional brands to Arnage are **Aléop, NOMAD and Rémi** (e.g. `Aléop P30 857065`). - **The real Spot FR answer undercut the Arnage decision:** TGV INOUI 5210 CDG 08:48 → Le Mans 10:30 (7.2 km from the spot), **2h50 wait**, Aléop P30 13:20 → Arnage 13:25 (2.0 km) — **4h37 total**. Shipping only the Arnage endpoint would have made the flagship French spot's headline a 4h37 journey with a 2h50 platform wait.
- **USER DECISION — "show both", zero extra API calls.** Every station on a journey within the existing 30 km rule becomes an alighting option, because the change station is already inside the body we fetch. The rider chooses "off at Le Mans 10:30, 7.2 km" or "stay to Arnage 13:25, 2.0 km". The rule is explicitly NOT "nearest station wins" — Le Mans is farther but arrives 2h50 earlier.
- **Lead:** `alightingOptions: [{ stationName, stationId, arrivalTime, distanceKm, durationMinutes, changes }]`, in journey order, within 30 km, distances as haversine. Top-level `durationMinutes` / `changes` / `station` keep their current meaning — the full run to the canonical nearest station. No new endpoint, no new API calls.
- **Lead:** a change of ≥ 90 minutes renders as "2h50", not "170 min". `formatDuration(170)` already returns exactly that, so it's a threshold on the existing formatter, not new code.
- **Lead:** section-level `display_informations.physical_mode` is untrustworthy — the 5-minute Aléop hop is labelled "Train grande vitesse". 7.5's stop_area-level filter is unaffected; nothing may infer a leg's mode from it.
- **Lead:** alighting options are filtered, not capped. Order: within 30 km → **dominance** (drop X if some Y is both no later and no farther) → **materiality** (walking from the closest outward, keep an earlier/farther option only if it arrives ≥ **30 minutes** before the last option KEPT — re-anchored on survivors, never on dropped options; with A 14:00, B 13:40, C 13:20, B drops against A and C is then compared to A, so C is kept) → sort by arrival time. Validated against the captured body: journey 1 → 2 options (dominance also collapses Le Mans's two calls, 10:30 and 13:20); journey 3 → 4 stations collapse to 2; journey 2's five options are a genuine Pareto chain spanning only 27 minutes, so materiality reduces it to the closest station alone. The 30 minutes is a named constant, tunable without a contract change; setting it to zero restores every Pareto option. All 45 stop_area ids and coordinates came from nested stop_area objects — nothing inferred from id patterns.
- **Lead:** total SNCF calls spent today is **four**. No further calls are authorised; the replacement-call authorisation issued when the body looked lost was withdrawn once it was found.
