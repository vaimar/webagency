> **Philosophy:** Anti-Cauchemar / Frozen Summer — honest prices, no brochure language, dark-mode clarity

## Problems that were fixed

### 1. Invisible text on the hero flight card

**Root cause:** `App.css` was referencing CSS custom properties that don't exist in the project (`--color-text`, `--color-primary`, `--color-muted`, `--color-border`). Their fallback values were dark navy (`#102033`, `#173c63`) — near-identical to the card's own dark-gradient background. Everything was invisible.

**Fix:** All `var(--color-*, fallback)` references in the hero card section of `App.css` were replaced with explicit, high-contrast Frozen Summer palette values:

| Element | Before | After |
|---|---|---|
| City code / name | `#102033` (invisible) | `#f1f5f9` / `#e2e8f0` |
| Airport name | `#64748b` (barely) | `#94a3b8` |
| Big fare price | `#173c63` (invisible) | `#f8fafc` |
| Honest total accent | — | `#7dd3fc` (sky blue) |
| Card borders | `#e5e7eb` | `rgba(148, 163, 184, 0.24)` |
| Booking link buttons | light-mode blue | `rgba(125, 211, 252, 0.12)` bg / `#93c5fd` text |
| Ryanair primary button | dark invisible navy | `#1e40af` (clear blue) |

### 2. `DUBDublinDublin Airport` display bug

**Root cause:** Same color issue — the three `<span>` elements (IATA code, city name, airport name) inside the `.flight-card--hero__city` flex-column were all dark-on-dark, making them appear to merge visually. The layout was correct but unreadable.

**Fix:** Added explicit `display: block` to each span (`city-code`, `city-name`, `airport-name`) and corrected all their colors. Now they stack clearly and distinctly:

```
DUB          ← large, white
Dublin       ← medium, light
Dublin Airport  ← small, muted
```

---

### 3. Wrong price hierarchy (total shown first, base fare second)

**Before:** The hero and standard card both displayed the *estimated total entry price* as the main big number, with the raw Ryanair base fare in small print below. This confused users — the headline price wasn't what Ryanair advertises.

**After (both hero + standard card):**
- **Big number = base flight fare** (what Ryanair charges, exactly as advertised)
- **Below = "Honest total: €X"** (only when known extras exist — cabin bag, transfer)

This respects the principle: show what you *will pay to Ryanair*, then show what you *might actually spend*.

```
Flight fare
€35.54           ← big, prominent

Honest total: €59.54   ← secondary, sky blue
```

---

### 4. Misleading "Airport transfer estimate €0" line

**Problem:** When the backend returned `airportShuttleEstimate = 0` (i.e., transfer cost unknown / not added), the TruthCard was displaying `"Airport transfer estimate €0"` — which looked broken, and coincidentally produced the same number as the taxi warning text ("60 EUR minimum taxi"), creating confusion.

**Fix:** `TruthCard.tsx` now suppresses any line item whose value is `0`. Only non-zero extras are shown in the breakdown. The section is also renamed from the vague **"What can change the real cost"** to **"Price breakdown"**.

---

### 5. Pre-existing TypeScript error

`flight.antiCauchemar` has type `AntiCauchemarAnalysis | undefined` but `TruthCardProps.truth` expected `AntiCauchemarAnalysis | null`. Fixed with `flight.antiCauchemar ?? null` at both TruthCard call sites in `FlightCard.tsx`.

## New feature: Frontend taxi-cost estimator

### Motivation

The backend was issuing warnings like *"60 EUR minimum taxi to city centre"* for IBZ (Ibiza). The actual taxi fare from Ibiza Airport to the port is roughly **€13 daytime / €16 at night** (8 km road). The figure was wrong by 4×.

### Source

Logic ported from [VanDerCroix/Taxi-fare-calculator](https://github.com/VanDerCroix/Taxi-fare-calculator) — a Google Maps-based Peruvian taxi meter. The useful part is the **Haversine formula** it uses to compute straight-line GPS distance. We adapted it with European airport coordinates and per-country meter rates.

### New file: `src/services/transferEstimate.ts`

```
src/services/transferEstimate.ts
├── haversineKm(a, b)          Haversine formula → straight-line km
├── TAXI_RATES                 18 country rate tables (€/km + flag fall + night multiplier)
│                              Sources: UITP, national taxi associations, 2024-25 tariffs
├── AIRPORT_DATA               80 airports: GPS coords + city-centre GPS + public transport alt
├── estimateAirportTransfer()  Main function → returns TransferEstimate | null
├── formatTransferLabel()      "~€16 (night rate)"
└── getArrivalHour()           Parses ISO datetime → 0-23 for night detection
```

**How it works:**
1. Look up `AIRPORT_DATA[airportCode]`
2. Run Haversine on airport GPS → city-centre GPS → straight-line km
3. Multiply ×1.3 for road overhead
4. Apply `flagFall + roadKm × ratePerKm`
5. If arrival hour is 22:00–06:00, apply `nightMultiplier` (typically 1.25–1.50)
6. Return fare, distance, night flag, and public transport alternative if known

**Validated estimates:**

| Route | Road km | Daytime | Night |
|---|---|---|---|
| IBZ (Ibiza airport → port) | 8.2 | **€13** | **€16** |
| BVA (Beauvais → Paris) | 89.4 | **€139** | — |
| STN (Stansted → London) | 63.6 | **€184** | — |
| DUB (Dublin airport → city) | 10.0 | ~€14 | ~€21 |
| BCN (El Prat → Barcelona) | 17.9 | ~€23 | ~€28 |

BVA and STN remain real traps — the estimates confirm it factually.

### Where it renders

When the backend returns `airportShuttleEstimate = 0` (unknown / not added), `TruthCard.tsx` now calls `estimateAirportTransfer(destinationCode, arrivalHour)` and displays a green **"Taxi estimate"** panel:

```
TAXI ESTIMATE · 8.2 km · night rate
~€16 (night rate)  or  [no public transport]

Calculated from airport → city centre.
Not added to the price — verify before booking.
```

Where public transport exists, the alternative is shown inline:
```
~€23  or  Aerobus / Metro L9 ~€5 (35 min)
```

The estimate is **never added to `estimatedEntryPrice`** — it's purely informational, clearly labelled as a calculation, and defers to the user to verify. This is correct Anti-Cauchemar behaviour: surface costs, don't invent totals.
